## 0. 三种启动方式

| 方式 | 命令 | 适用场景 |
| --- | --- | --- |
| 命令行演示 | `python demo.py` | 端到端跑一遍全链路(脱敏→入库→问答→生成),无需 API Key |
| Web 界面 | 双击 `启动前端.bat`(首次自动构建前端)或 `python -m uvicorn api.main:app --host 127.0.0.1 --port 8000` | 日常使用,浏览器访问 `http://127.0.0.1:8000` |
| 前端开发模式 | `python -m uvicorn api.main:app --port 8000` + `cd frontend && npm run dev` | 改前端代码热更新,`http://localhost:5173`(`/api` 自动代理) |
| 框架自检 | `python -m app_core` | 验证配置/日志/框架就绪,打印当前配置摘要 |

代码方式(推荐,复用单例):

```python
from service import get_system
sys_ = get_system()   # 进程内单例,首次调用时自动装配全部模块
```

## 1. service.py —— System 门面(编程入口)

所有模块在这里装配,日常**只需用这一个类**。

### 1.1 会话管理

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| 新建会话 | `create_session(user_id: str = "") -> Session` | 返回带 `session_id` 的会话对象 |
| 列出会话 | `list_sessions() -> list[Session]` | 全部会话 |
| 查看历史 | `session_history(session_id) -> list[Message]` | 返回该会话全部消息(副本) |

```python
s = sys_.create_session(user_id="u001")
sys_.session_history(s.session_id)   # -> [] 初始为空
```

> ⚠️ 会话存在**内存**中,重启服务即清空。

### 1.2 知识与检索

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| 知识入库 | `ingest_doc(title, content, source="") -> int` | 切片 → 写入全文索引 + 向量库,返回切片数 |
| 检索 | `search(query, top_k=None) -> list[RetrievedChunk]` | 双路召回 + 融合排序,`top_k` 缺省取配置(5) |

```python
n = sys_.ingest_doc("智能门锁 S1 参数", "指纹+密码开锁,售价 899 元...")
hits = sys_.search("门锁 价格")        # hits[0].text / .final_score / .rank
```

> 全文索引(FTS)在内存,重启后需重新 `ingest_doc`;向量库(Chroma)持久化在 `data/chroma/`,同一文档重入库会原地覆盖(内容哈希 id)。

### 1.3 售前问答

```python
ans = sys_.ask(session_id, "智能门锁 S1 的价格和参数?")
ans.answer          # 回答文本
ans.source_chunks   # 引用的知识片段 list[RetrievedChunk]
ans.trace           # 执行轨迹 [{"step","stage","tool"}]
ans.degraded        # True = 走了降级(工具/模型失败或超步)
```

`ask` 自动完成:记录用户消息 → 携带会话历史推理 → 记录回答(会话隔离,见 G-4)。

### 1.4 内容生成

```python
results = sys_.generate_content(
    session_id,
    {"product_id": "P001", "name": "智能门锁 S1"},
    stage="all",          # "all" | "topic" | "copy" | "script"
)
for gc in results:
    gc.stage.value   # topic / copy / script
    gc.status.value  # done / failed(该阶段失败已跳过)
    gc.content       # 生成文本;failed 时为 ""
    gc.task_id       # 任务 ID,用于断点恢复
```

> `product_info["name"]` 会直接进入提示词,请传可读名称。推理模型下 `all` 约需 1~3 分钟。

### 1.5 数据管道

```python
masked, report = sys_.process_data(records)   # records: list[dict],见 §3
report.total_records / report.mask_hits / report.samples
```

## 2. app_core —— 模块 A:企业级框架

### 2.1 config(配置)

优先级:**环境变量 > .env > config.yaml > 内置默认值**。

| 配置项(config.yaml 分组.键) | 环境变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| `llm.model` | `LLM_MODEL` | `mock` | `mock` = 离线模板生成 |
| `llm.max_tokens` | — | `2048` | 推理模型请勿过低 |
| `llm.temperature` | — | `0.2` | |
| `llm.api_format` | `LLM_API_FORMAT` | `""` | `anthropic`/`openai`;留空按 Base URL 自动识别 |
| — | `LLM_API_KEY` / `LLM_BASE_URL` | 空 | 两项都有值才走真实 LLM |
| `retrieval.top_k` | — | `5` | 融合后返回条数 |
| `retrieval.fts_weight` / `vector_weight` | — | `0.5` / `0.5` | 双路融合权重 |
| `retrieval.chunk_size` / `chunk_overlap` | — | `512` / `64` | 切片窗口与重叠 |
| `retrieval.vector_backend` | `RETRIEVAL_VECTOR_BACKEND` | `chroma` | 未装 chromadb 自动回退 `simple` |
| `retrieval.embedding_model` | `EMBEDDING_MODEL` | 空 | 空=内置特征哈希向量 |
| `agent.max_steps` | — | `10` | ReAct 最大步数,超步降级 |
| `agent.tool_retries` | — | `2` | 工具调用重试次数 |
| `content.retries` | — | `3` | 内容生成单阶段重试 |

敏感项只从 `.env`/环境变量读取,不落库、不写日志、不传前端。

### 2.2 llm(统一 LLM 客户端)

```python
from app_core.config import LLMConfig
from app_core.llm import LLMClient

llm = LLMClient(LLMConfig())            # 空 key -> MockLLM(离线)
text = llm.generate(messages, mode="answer")
```

- `messages`:`[{"role": "system/user/assistant", "content": "..."}]`
- `mode`:`answer` / `topic` / `copy` / `script` / `chat`(**仅 Mock 使用**,用于返回不同结构的占位内容;真实接口忽略)
- `overrides`:`max_tokens` / `temperature` / `retries` 可单次覆盖
- 失败行为:经 `safe_call` 重试 2 次(退避 1s/2s),仍失败返回 `"[降级] 模型暂不可用:<原因>"`,**不抛异常**
- 格式适配:Base URL 含 `/coding` 或 `anthropic` → Anthropic Messages 格式(如火山方舟 coding 端点);否则 OpenAI `/chat/completions`。可用 `LLM_API_FORMAT` 强制指定

### 2.3 safe_call(可靠性核心,G-5)

```python
from app_core.safe_call import safe_call

result = safe_call(fn, *args,
    retries=2,           # 重试次数(共执行 retries+1 次)
    delay=1.0,           # 首次重试前等待秒数
    backoff=2.0,         # 退避乘子:第 n 次等待 delay*backoff^(n-1)
    degraded_value=None, # 最终失败时返回的兜底值
    on_failure="degrade",# "degrade"=返回 DegradedResult;"raise"=抛出
    **kwargs)
# result.degraded == True 时:result.value / result.reason
```

### 2.4 session(会话存储)

`SessionStore`:`create(user_id="")` / `list()` / `get(sid)` / `add_message(sid, role, content, source_chunks=None)` / `history(sid)`(返回副本)。会话不存在时 `add_message` 自动创建。

### 2.5 models / logger / errors

- **models**:全部强类型 dataclass。常用:`Session`、`Message`、`Chunk`、`KnowledgeDoc`、`RetrievedChunk`(含 fts_score/vector_score/final_score/rank)、`MaskReport`、`GeneratedContent`;枚举:`PiiType`(phone/id_card/email)、`MaskStrategy`(mask/replace)、`ContentStage`、`ContentStatus`
- **logger**:`get_logger("模块名")`,格式固定 `时间 级别 [模块] 消息`;禁止打印 Key/PII 原文
- **errors**:`BaseAppError` 基类;可重试类继承 `RetryableError`(`ToolError`/`LLMError`);`DegradedError` 标识已降级路径

## 3. data_pipeline —— 模块 B:数据管道

一行跑完(清洗 → 去重 → 脱敏):

```python
from data_pipeline.masker import run_pipeline
masked, report = run_pipeline(records)   # records: list[dict]
```

### 3.1 输入数据格式

每条记录是 dict,**文本字段**为 `content` / `text` / `message` / `content_text` 之一(脱敏和清洗只作用于这些字段),推荐结构:

```python
{"session_id": "s1", "user_id": "u1", "role": "user", "content": "..."}
```

文件导入用 `data_pipeline.loader.load_records(path)`,支持:
- **CSV**:首行列名需含 `session_id, user_id, role, content`
- **JSON**:`[{"...": "..."}]` 数组;**JSONL**:每行一个 JSON 对象

### 3.2 各环节参数

| 函数 | 关键参数 | 行为 |
| --- | --- | --- |
| `cleaner.clean(records)` | — | 折叠空白/换行;None→"";文本字段全空的记录丢弃 |
| `dedupe.dedupe(records, similarity_threshold=0.0)` | `>0` 启用 Jaccard 相似去重 | 默认按内容哈希去完全重复 |
| `masker.mask(records, rules=None, sample_limit=5)` | `rules` 自定义规则;`sample_limit` 报告抽样条数 | 返回(脱敏记录, MaskReport) |
| `session_split.split_sessions(records, id_field="session_id", time_field="timestamp", time_gap_minutes=30)` | 有 id 按 id 分组;无 id 按时间间隔切分 | 返回 `[{"session_id", "messages": [...]}]` |

### 3.3 脱敏规则与报告

默认规则(`rules.py`,**身份证必须先于手机号**,避免内部片段误命中):

| 类型 | 正则 | 策略 | 效果 |
| --- | --- | --- | --- |
| id_card | 18 位 `\d{17}[0-9Xx]` | mask | `110101********8888` |
| phone | `1[3-9]\d{9}` | mask | `138****5678` |
| email | 标准邮箱 | replace | `<EMAIL>` |

自定义规则示例:

```python
from app_core.models import MaskRule, MaskStrategy, PiiType
from data_pipeline.masker import mask

rules = [MaskRule(pii_type=PiiType.PHONE, pattern=r"1[3-9]\d{9}",
                  mask_strategy=MaskStrategy.MASK, enabled=True)]
masked, report = mask(records, rules=rules)
report.mask_hits   # {"phone": 3} 各类型命中次数
report.samples     # [{"field","pii_type","before","after"}] 脱敏前后对照
```

## 4. retrieval —— 模块 C:混合检索

### 4.1 推荐用法(经门面)

```python
from retrieval.fts import FTSIndex
from retrieval.vector import get_vector_store
from retrieval.hybrid import HybridRetriever

retriever = HybridRetriever(
    FTSIndex(":memory:"),                 # 全文路(:memory: 或 sqlite 文件路径)
    get_vector_store(config),             # 向量路:chroma / simple 自动选择
    chunk_size=512, overlap=64, top_k=5,
    fts_weight=0.5, vector_weight=0.5,
)
n = retriever.ingest(KnowledgeDoc(title="...", content="..."))  # 返回切片数
results = retriever.search("查询词", top_k=5)  # list[RetrievedChunk] 按 final_score 排序
```

### 4.2 各组件要点

| 组件 | 要点 |
| --- | --- |
| `chunker.chunk_doc(doc, size, overlap)` | 滑动窗口;标题并入首切片(可被检索);chunk_id = 内容哈希(标题\|序号\|文本),重复入库幂等 |
| `fts.FTSIndex(db_path)` | 优先 SQLite-FTS5(bm25);环境不支持自动回退内存倒排;中英文混合分词(中文逐字/英文逐词) |
| `vector.get_vector_store(config)` | `chroma` 未装 → 回退 `simple`(内置特征哈希,离线确定性) |
| `vector.ChromaVectorStore` | 持久化 `./data/chroma`;add/query **显式传 embeddings**(与 chromadb 版本解耦);upsert 幂等 |
| `hybrid.HybridRetriever.search` | 双路各取 top_k×2 → 各自 min-max 归一化 → `final = fts_weight·f + vector_weight·v` → 取 top_k |

### 4.3 检索质量评测(G-2)

```bash
python -m retrieval.eval        # 直接输出三引擎对比报告
```

```python
from retrieval.eval import run_eval, print_report
print_report(run_eval(top_k=5))  # fts / vector / hybrid 命中率 + 逐条明细
```

评测集 `data/eval_qa.json`:每条 `{"query", "expected"(文档标题)}`。评测固定用 SimpleVectorStore 保证离线可复现。

## 5. agents/pre_sale —— 模块 D:售前咨询 Agent(ReAct)

### 5.1 状态机与接口

```
START → think →(有动作)→ act →(未超步)→ think ...(循环)
             └(无动作)→ respond → END
act 失败(retry≤2 耗尽)→ degrade → END;超 max_steps=10 → degrade → END
```

```python
ans = agent.run(session_id, user_query, history=[{"role","content"}, ...])
# AgentAnswer: answer / source_chunks / trace / degraded / reason
```

### 5.2 工具与路由(ReAct 的 think/act)

`ToolRouter` 按关键词选择工具,**每轮只执行一次工具调用**后进入回答(单跳设计,保证收敛):

| 问题含关键词 | 调用工具 | 参数来源 |
| --- | --- | --- |
| 库存/有没有货/缺货/现货/有货/stock | `get_stock` | 问题中的 `P001`~`P999`,无则整句 |
| 参数/规格/型号/价格/多少钱/配置/详情 | `get_product_info` | 同上 |
| 其他 | `search_knowledge` | 整句作为检索 query |

`Tools(retriever, catalog)` 的三个工具:

```python
tools.search_knowledge(query)              # -> list[RetrievedChunk]
tools.get_product_info("P001")             # -> {"product_id","name","specs","category"}
tools.get_stock("P001")                    # -> {"product_id","name","stock","available"}
```

商品目录 `ProductCatalog.sample()` 是内置演示数据(P001 门锁 132 件 / P002 扫地机 45 件 / P003 音箱 0 件)。**接真实商品库**:仿照 sample() 返回 `products`、`stock` 两个 dict,传给 `Tools(...)` 即可,其余不用改。

`build_langchain_tools(tools)` 把三工具封装为 LangChain `Tool` 列表(供 LangGraph tool-calling 节点或外部框架绑定)。

## 6. agents/content —— 模块 E:内容生成 Agent(SubGraph)

### 6.1 生成与断点恢复

```python
from agents.content.graph import ContentAgent
from agents.content.persist import Checkpointer

agent = ContentAgent(llm, retries=3, checkpointer=Checkpointer())  # 持久化到 ./data/checkpoints

results = agent.generate("sid", {"name": "智能门锁 S1"}, stage="all", task_id=None)
# 任一阶段失败:重试 ≤3 → 仍失败产出 status=failed 的片段,继续后续阶段(不中断)

task_id = results[0].task_id                  # 也可查 data/checkpoints/*.json 文件名
restored = agent.resume(task_id, {"name": "智能门锁 S1"})   # 只重跑未 done 的阶段
```

- `generate` 返回后状态**总是**写入 JSON Checkpointer(跨进程可恢复)
- LangGraph 图内另挂 `InMemorySaver`(进程内断点);跨进程恢复用 `resume`
- `Checkpointer.save/load/delete(task_id)`

### 6.2 三阶段提示词(stages.py)

| 阶段 | 提示词模板 |
| --- | --- |
| topic | `为产品【{name}】生成 3 个选题。` |
| copy | `为产品【{name}】生成推广文案。` |
| script | `为产品【{name}】生成短视频脚本。` |

要改生成风格/加要求,直接编辑 `agents/content/stages.py` 中对应函数的提示词。

## 7. frontend / api —— 模块 F:Vue 3 前端 + FastAPI 网关

启动:双击 `启动前端.bat`(首次自动 `npm install && npm run build`,之后 `python -m uvicorn api.main:app` 同端口 `8000` 托管页面与接口);开发模式见 §0。

技术栈:Vue 3 + Vite + Element Plus(深色)+ ECharts;后端 `api/main.py` 把 `System` 门面包装为 REST API(`/api/*`),内容生成为后台任务 + 轮询(逐阶段真实进度)。

| 页面 | 操作 |
| --- | --- |
| 系统总览 | 六模块运行状态、关键指标(文档/切片/会话/消息/任务)、运行环境(LLM 模式/检索配置) |
| 智能问答 | 聊天框提问;回答附 ReAct 推理轨迹与引用来源;顶栏切换/新建会话(隔离 G-4) |
| 知识入库 | 「一键载入示例知识库」/ 填标题+内容点「入库」/ 检索验证(含 fts·向量得分明细) |
| 内容生成 | 选产品卡片(P001~P003,含库存)+阶段 → 「生成」;阶段进度条;失败阶段可「续跑」 |
| 数据管道 | 示例数据 / 上传 CSV·JSON·JSONL / 粘贴 JSON;漏斗图、PII 命中图、脱敏对照表、预览、报告 JSON |

主要 REST 接口(全部离线可跑,见 `tests/test_api.py`):`GET /api/health|stats|sessions|knowledge|products|content/tasks`、`POST /api/sessions|knowledge/ingest|knowledge/sample|knowledge/search|ask|content/generate|content/resume|pipeline/run|pipeline/sample|pipeline/upload`。

> 重启后:会话历史与全文索引清空,需重新「一键载入」;向量库持久不受影响。单 worker 部署(状态在进程内存)。

## 9. 常见任务速查

**换真实商品数据** → 自定义 `ProductCatalog`(§5.2)
**换 LLM/服务商** → 改 `.env` 三项(+`LLM_API_FORMAT`,§2.1)
**真实语义向量** → `.env` 加 `EMBEDDING_MODEL=<OpenAI 兼容 embedding 模型名>`(复用 LLM Key/地址)
**调检索权重** → `config.yaml` 的 `retrieval.fts_weight/vector_weight`(和为 1)
**改生成文风** → `agents/content/stages.py` 提示词
**自定义脱敏规则** → `MaskRule` 传给 `mask(records, rules=...)`(§3.3)
**断点续跑生成任务** → `agent.resume(task_id, product_info)`(§6.1)
**离线演示/测试** → 不配 `.env`,一切自动走 Mock 与 simple 后端
